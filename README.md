## დაყენება და გაშვება

საჭიროა Python 3.10+ და ინტერნეტთან კავშირი (NBG API).

```bash
python -m venv venv
venv\Scripts\activate        # Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
python main.py               # ან: python main.py path/to/requests.json
```

შედეგები იქმნება `output/` საქაღალდეში:

- `processed.json` — გასუფთავებული მიმართვები, დამატებითი ველებით `amount_gel`, `rate` და `rate_source`;
- `rejected.json` — გამორიცხული ჩანაწერები (`record` — ორიგინალი, `reasons` — მიზეზები);
- `summary.json` — სტატისტიკა და გასწორებების ჟურნალი (`corrections`).

შეიძლება რამდენიმე გამორიცხვის მიზეზი ჰქონდეს. ყველა გასწორება ფიქსირდება

- წელი პირველ ადგილზეა, ამიტომ რიგი YYYY.MM.DD სტანდარტულია.

**REQ-018** — თარიღი `5 მაისი 2026` → `2026-05-05`
- ქართული თვის სახელი ცალსახად ითარგმნება.

**REQ-019** — ვალუტა `$` → `USD`

### სხვა გადაწყვეტილებები

  ჯერ კონვერტაცია არ არის და GEL/USD/EUR-ის შერევა არასწორი იქნებოდა.
  მოცემულია ორი მაჩვენებელი: ყველა ჩანაწერით (`average`) და მხოლოდ 0-ზე მეტი თანხით
  (`average_nonzero`), რადგან 0-იანი მიმართვები საშუალოს ხელოვნურად ამცირებს.
- **REQ-023** ფაილში არ არის (id-ების რიგში ნახტომია). ეს არ ითვლება შეცდომად —
  დაკარგულ ჩანაწერს ვერ აღვადგენთ.
- `channel` და `text` ნორმალიზდება (პატარა ასოები, ზედმეტი სივრცეების მოშორება).

## ნაწილი 2: თანხების გადაყვანა ლარში

### გამოყენებული API

საქართველოს ეროვნული ბანკის (NBG) საჯარო API:

```
GET https://nbg.gov.ge/gw/api/ct/monetarypolicy/currencies/en/json/?date=2026-02-03
```

პასუხი (შემოკლებით):

```json
[{"date": "2026-02-03T00:00:00.000Z",
  "currencies": [{"code": "USD", "quantity": 1, "rate": 2.6902, ...}, ...]}]
```

### როგორ მუშაობს

- USD/EUR მიმართვისთვის გამოიყენება **მიმართვის თარიღით** დადგენილი კურსი.
- GEL-ის კურსია `1.0`, API არ გამოიძახება.
- ერთ თარიღზე API-ს ერთი მოთხოვნა იგზავნება, პასუხი ინახება ქეშში.
  ერთსა და იმავე თარიღზე API მეორედ არ გამოიძახება.
- კურსი ითვლება ერთ ერთეულზე: `rate / quantity`. USD/EUR-ს `quantity` = 1 აქვს,
  მაგრამ ზოგ ვალუტას (მაგ. AMD) 1000, ამიტომ ასე უფრო საიმედოა.
- `processed.json`-ში ემატება `rate_source`, რომ ჩანდეს, საიდან მოვიდა კურსი:
  - `gel` — თანხა უკვე ლარშია;
  - `nbg_request_date` — მიმართვის თარიღის კურსი;
  - `nbg_current` — მიმდინარე კურსი (სარეზერვო ვარიანტი);
  - `unavailable` — კურსი ვერ მოიძებნა.

### შეცდომების დამუშავება

1. ყოველ მოთხოვნას აქვს 10 წამიანი `timeout`.
2. Timeout, კავშირის შეცდომა, 5xx პასუხი ან არავალიდური JSON — მოთხოვნა მეორდება
   3-ჯერ, მზარდი პაუზით (1 წმ, 2 წმ).
3. 4xx პასუხზე მოთხოვნა არ მეორდება, რადგან განმეორება შედეგს არ შეცვლის.
4. თუ მიმართვის თარიღის კურსი ვერ მოიძებნა, გამოიყენება მიმდინარე კურსი
   (`rate_source: nbg_current`).
5. თუ API საერთოდ არ პასუხობს, `amount_gel` და `rate` არის `null`,
   `rate_source` — `unavailable`, პროგრამა კი მუშაობას აგრძელებს.
6. წარუმატებელი შედეგიც ინახება ქეშში, რომ ყოველ ჩანაწერზე 3 ცდა თავიდან არ დაიწყოს.

შემოწმებული სცენარები:

- არარსებული მისამართი (`NBG_API_URL=https://nbg.invalid/api/`): პროგრამა
  არ ჩერდება, USD/EUR ჩანაწერებს ენიჭება `unavailable`, GEL ჩანაწერები კი გადაიყვანება.
- თარიღიანი მოთხოვნის ხელოვნური შეცდომა: გამოიყენება მიმდინარე კურსი (`nbg_current`).

## სირთულეები და მათი გადაჭრა

- **API-ის დოკუმენტაცია.** NBG-ის საიტზე API-ს ცალკე დოკუმენტაცია არ არის.
  endpoint-ს იყენებს კურსების გვერდი (nbg.gov.ge/monetary-policy/currency).
  პარამეტრები და პასუხის სტრუქტურა `curl`-ით შემოწმდა.
- **`currencies` პარამეტრი არასაიმედოა.** API შეცდომის ნაცვლად ცარიელ სიას `[]` აბრუნებს:
  - `currencies=USD,EUR` — ყოველთვის `[]`;
  - `currencies=USD&currencies=EUR` — `date`-ით მუშაობს, `date`-ის გარეშე კი `[]`.

  ეს მეორე შემთხვევა სარეზერვო (მიმდინარე) კურსის ტესტირებისას გამოჩნდა.
  გადაწყვეტა: ფილტრი საერთოდ არ გამოიყენება. ერთი მოთხოვნა ყველა ვალუტას
  აბრუნებს (~40), USD და EUR კი კოდში ამოირჩევა. ცარიელი პასუხი შეცდომად ითვლება.
- **შაბათ-კვირა.** REQ-005-ის თარიღი (2026-02-14) შაბათია. API ამ დღისთვისაც აბრუნებს
  კურსს, ამიტომ ცალკე დამუშავება არ დასჭირდა.

- თავიდან გაკეთებისას სარეზერვო ვარიანტი (მიმდინარე კურსი) ცალკე შევამოწმე:
  თარიღიან მოთხოვნაზე შეცდომა ხელოვნურად გამოვიწვიე. შედეგი
  `rate_source: unavailable` იყო, ანუ სარეზერვო ვარიანტი არ მუშაობდა.
- ლოგში ჩანდა მიზეზი: `NBG rates unavailable for current: empty response`.
  `curl`-ით დადასტურდა, რომ `date`-ის გარეშე ორი `currencies` პარამეტრით
  API ცარიელ სიას `[]` აბრუნებს, ერთით ან ფილტრის გარეშე კი კურსებს.
- ეს შეცდომა პირველ ვერსიაშიც იყო. მაშინ ტესტმა შემთხვევით გაიარა, რადგან
  API იმ მომენტში სხვანაირად პასუხობდა.
- გადაწყვეტა: ფილტრი მოიხსნა, API ყველა ვალუტას აბრუნებს და USD/EUR
  კოდში ამოირჩევა. ამის შემდეგ სამივე სცენარი (თარიღის კურსი, მიმდინარე
  კურსი, მიუწვდომელი API) ხელახლა შემოწმდა.
